# ドメイン用語集・ステータスモデル（初版）

出典: 既存標準業務マニュアル（取引共通：購買部門／依頼部門／サプライヤ、マスタ管理、カタログ管理）。
Proco ではこの用語を **標準名** とし、顧客ごとの呼び替えは表示名辞書（tenant-config）で行う。

## 1. アクターとロール

| 標準名 | 英語名（コード） | 説明 |
|---|---|---|
| バイヤ企業グループ | company_group | テナント単位。配下に複数の会社・組織を持つ |
| 会社 | company | バイヤ企業グループ内の法人 |
| 組織（部門・拠点） | org_unit | 階層構造。ユーザーは本務／兼務で複数所属できる |
| 依頼者（申請者） | requester | カタログ購買・見積申請・発注申請・検収登録を行う |
| 承認者 | approver | 見積承認・発注承認・検収承認・選定承認を行う。承認ルールで決まる |
| 購買部門担当者 | buyer | 担当割振、見積展開、選定、代理回答・代理受注、ダウンロードセンター |
| 割振担当者 | buyer_dispatcher | 担当者未定案件に購買担当者を割り振る権限 |
| 参照者 | watcher | 案件の閲覧のみ |
| マスタ管理者 | master_admin | 会社グループ／会社／組織／ユーザー／承認ルール等のマスタ管理 |
| サプライヤ | supplier | 見積回答・受注・納品登録。オンライン／オフライン（FAX・メール）の2種 |
| サービス提供会社 | service_provider | Proco 運営側。バイヤスイッチ（機能ON/OFF）を設定 |

## 2. 主要エンティティ

| 標準名 | 英語名 | 説明 |
|---|---|---|
| 案件 | case | 1件の購買単位。見積案件（Q番号）と発注案件（P番号）がある |
| 明細 | line | 案件内の品目行。分納・分割・按分・検収は明細単位 |
| 見積依頼 | rfq | 購買部門（またはセルフ見積で依頼部門）からサプライヤへの依頼。最大30社 |
| 見積回答 | quote | サプライヤ（または代理）からの回答。有効期限・発注回数制限・単価・納期 |
| 見積選定 | award | 採用サプライヤの決定。採用理由・支出抑制額・通知要否 |
| 発注 | order | 発注申請→承認でサプライヤへ注文 |
| 受注 | order_confirmation | サプライヤの受注登録（納品予定日）／受注辞退 |
| 納品登録 | delivery | サプライヤの納品登録。分納可。現品票・納品書 |
| 検収 | acceptance | 依頼者の検収登録→承認。明細単位、分納ごと。検収日は納品日以降・当日まで |
| 締め処理 | closing | 検収完了明細を支払対象に確定。支払通知書 |
| 品目カテゴリ | item_category | 3階層。依頼テンプレート・承認ルール・サプライヤ推奨に紐づく |
| 依頼テンプレート | request_template | 品目カテゴリごとの入力項目定義（物品／役務） |
| カタログ | catalog | 内部カタログ／外部カタログ（PunchOut）。横串検索対象 |
| サプライヤマスタ | supplier_master | 会社情報・取引条件・支払条件・取適法判定・オフライン区分 |
| 内部指図 | internal_order | 明細に付与する指図コード（顧客により製番・研究テーマ等と呼ぶ） |
| 按分 | allocation | 明細の原価センタ×勘定科目の費用配分（比率／金額） |
| 納品先 | ship_to | MY納品先リスト。送り状に反映 |
| 管理項目 | custom_field | テナントが定義する追加項目（スロット） |
| ToDo | todo | ユーザーが処理すべき案件数 |
| ダウンロードセンター | download_center | 条件・列順を保存したテンプレートからCSV/Excel出力 |

## 3. 購買種別

| 種別 | コード | 概要 |
|---|---|---|
| カタログ購買 | CATALOG | カタログ検索→カート→発注申請→承認→受注→納品→検収 |
| 手配依頼 | ARRANGE | 見積取得〜発注まで購買部門に一任。選定承認と同時に発注申請 |
| 通常見積依頼 | RFQ_STANDARD | 見積取得・選定は購買部門、発注以降は依頼部門 |
| 概算発注 | ESTIMATE_ORDER | 概算のまま当初（仮）発注→仕様確定後に確定発注（補充） |
| セルフ見積 | RFQ_SELF | 依頼部門が直接見積依頼。上限金額超過時は購買部門へ |
| 事後申請 | POST_HOC | 発注済み案件の事後登録（優先度区分） |

## 4. ステータスモデル

### 4.1 見積案件（購買部門視点）
```
担当者未定 → 交渉前 → 交渉中 → 決定前 → 決定承認待 → 報告済み
              ↓差戻し        ↑再依頼       ↓決定差戻し / 決定引戻し
            取下げ
```
| ステータス | コード |
|---|---|
| 担当者未定 | UNASSIGNED |
| 交渉前 | PRE_NEGOTIATION |
| 差戻し | RETURNED |
| 交渉中 | NEGOTIATING |
| 再依頼 | RE_REQUESTED |
| 決定前 | ALL_ANSWERED |
| 決定承認待 | AWARD_PENDING_APPROVAL |
| 決定引戻し | AWARD_WITHDRAWN |
| 決定差戻し | AWARD_RETURNED |
| 報告済み | REPORTED |
| 取下げ | CANCELLED |

### 4.2 見積案件（依頼部門視点）
見積承認待ち / 差戻し / 引戻し / 回答待ち / 選定相談中 / 採用なし / 回答あり / 発注済み / 保留 / 取下げ

### 4.3 発注以降（案件・明細）
```
発注承認待ち → 受注待ち → 納品待ち → 未検収 → 検収承認待ち → 検収完了 → 支払締め済み
   ↓発注差戻し/引戻し  ↓受注辞退   ↓発注取消同意待ち     ↓検収差戻し/引戻し   ↓支払保留
                   取下げ
```
| ステータス | コード |
|---|---|
| 発注承認待ち | ORDER_PENDING_APPROVAL |
| 発注差戻し | ORDER_RETURNED |
| 発注引戻し | ORDER_WITHDRAWN |
| 受注待ち | AWAITING_CONFIRMATION |
| 受注辞退 | DECLINED |
| 納品待ち | AWAITING_DELIVERY |
| 発注取消同意待ち | CANCEL_PENDING_CONSENT |
| 未検収 | AWAITING_ACCEPTANCE |
| 検収承認待ち | ACCEPTANCE_PENDING_APPROVAL |
| 検収差戻し | ACCEPTANCE_RETURNED |
| 検収引戻し | ACCEPTANCE_WITHDRAWN |
| 検収完了 | ACCEPTED |
| 支払締め済み | CLOSED |
| 支払保留 | PAYMENT_ON_HOLD |
| 取下げ | CANCELLED |

案件ステータスは明細ステータスの集約（全明細一致で確定、不一致なら「一部」表示）。

### 4.4 ルール（マニュアル記載の業務制約）
- 見積依頼先は最大30社（特命・見積取得済みは除外）
- サプライヤへ見積依頼後は差戻し不可（交渉前のみ可）
- 検収日は納品日以降かつ当日まで。翌日以降は不可
- 検収登録にはサプライヤの納品登録が必要（オフラインサプライヤは代理受注／自動更新）
- 分納は納品実績ごとに検収を分ける
- 標準では「明細ごとに別サプライヤを採用」できない → Proco では標準機能候補 #1 で解消する
- ダウンロードセンター上限: CSV 1000件 / Excel 500件 → Proco では非同期出力で上限撤廃を検討

## 5. 通知（標準メール）
見積依頼通知、見積回答／辞退通知、注文依頼通知、注文承認／差戻し通知、受注処理通知、納品登録通知、検収督促（X日経過）、支払予定通知、発注申請承認完了通知。
テンプレートはテナントごとに差し替え可能とする（tenant-config: notification_templates）。
